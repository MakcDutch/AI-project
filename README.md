# Наскільки можна довіряти монокулярній глибині
 
Семестровий проєкт курсу «Штучний інтелект», УКУ, факультет прикладних наук, 2026.
 
Оцінка zero-shot моделей метричної глибини як єдиного джерела сприйняття для обльоту перешкод дроном DJI Tello.
 
**Дослідницьке питання.** Tello не має ні лідара, ні стереопари, ні далекоміра — єдине джерело геометрії сцени це одна RGB-камера. Сучасні foundation-моделі заявляють метричну глибину zero-shot, але їхні показники отримані на якісних знімках зі стандартних камер. Чи зберігається заявлена точність на дешевій камері і чи її достатньо, щоб дрон не врізався?
 
Пропозиція проєкту: [`docs/proposal/main.tex`](docs/proposal/main.tex).
 
## Поточний стан
 
Проєкт складається з трьох шарів. Два з них реалізовані й перевірені, третій — наступний крок.
 
| Шар | Стан | Де дивитись |
|---|---|---|
| Перцепція: похибка метричної глибини | виміряно офлайн | `results/validation_summary.csv` |
| Керування: реактивний контролер | реалізовано, перевірено в PX4/Gazebo | `outputs/simulation/` |
| З'єднання двох шарів у замкненому контурі | **ще не зроблено** | — |
 
Два відкриті розриви, які ми свідомо фіксуємо:
 
1. **Калібрування і валідаційні кадри зняті не з Tello**, а з камери смартфона (`results/calib_iphone_960.json`, 960×1280). Це зроблено навмисно як перший крок: на контрольованій камері відокремлюємо помилки методики вимірювання від артефактів дронового відео. Повторення тих самих вимірів на бортовій камері Tello — у плані до фінального захисту.
2. **У симуляції контролер працює на ground-truth глибині** з depth-сенсора X500, а не на передбаченій нейромережею. Тобто центральне питання проєкту поки перевірене лише на половині: окремо точність моделі, окремо поведінка контуру.
## Результати
 
Дві моделі, 40 опорних точок на п'яти знімках плоскої стіни з виміряною відстанню 1.35–3.23 м.
 
| Модель | AbsRel (GT=геометрія) | RMSE, м | Зміщення |
|---|---|---|---|
| DA3-metric-large | 0.096 | 0.233 | +9.6% |
| metric3d_vit_small | 0.172 | 0.388 | +17.2% |
 
Два висновки, які вже можна захищати:
 
**Metric3D ламається на ближній дистанції.** На 1.35 м зміщення +57%, δ₁ = 0. На всіх інших відстанях модель поводиться нормально (5–9%). Тобто вона систематично вважає стіну дальшою, ніж та є, саме в тій зоні, де дрон має починати гальмувати. Для задачі обльоту це найгірше можливе місце відмови.
 
**DA3 стабільно зміщений, і зміщення знімається перемасштабуванням.** Похибка тримається на рівні 8–11% на всіх відстанях, а після глобального перемасштабування (leave-one-frame-out) AbsRel падає з 0.096 до 0.013. Це підтверджує гіпотезу з пропоузалу: номінального масштабування за фокусною відстанню недостатньо, потрібне перекалібрування під конкретну камеру за кількома опорними вимірами.
 
Графік: `results/error_vs_distance.png`. Повна таблиця з довірчими інтервалами: `results/validation_summary.csv`.
 
Зауваження до метрик: δ₁ при порозі 1.25 на цьому наборі насичена (дорівнює 1.0 майже скрізь) і нічого не розрізняє. Показовими є AbsRel і зміщення.
 
### Симуляція замкненого контуру
 
PX4 SITL + Gazebo Harmonic, апарат X500, команди через MAVSDK Offboard. Три експерименти пройдені: чистий коридор, зупинка перед стіною, поведінка при застарілих кадрах глибини. В експерименті зі стіною мінімальний просвіт 1.33 м, шлях гальмування 0.28 м, час від виявлення до зупинки 0.98 с, зіткнень немає.
 
Деталі й команди відтворення: [`docs/software/GAZEBO_PX4_SIMULATION.md`](docs/software/GAZEBO_PX4_SIMULATION.md).

## Запуск
 
Потрібен Python 3.10+.
 
```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -e .
```
 
Тести:
 
```sh
python -m unittest discover -s tests -v
```
 
Контролер на синтетичних сценах:
 
```sh
python -m tello_nav --synthetic empty_corridor --output outputs/corridor.json
python -m tello_nav --synthetic center_obstacle --controller-config examples/controller.json --output outputs/obstacle.csv
python -m tello_nav --synthetic invalid_depth --output outputs/invalid.json
```
 
Відтворення метрик глибини (потребує `matplotlib`, `pandas` і завантажених ваг моделей):
 
```sh
python src/eval/validate.py
```
 
Симуляція PX4/Gazebo описана окремо в [`docs/software/GAZEBO_PX4_SIMULATION.md`](docs/software/GAZEBO_PX4_SIMULATION.md) — вона потребує збірки PX4 і встановлення `mavsdk`.
 
## Дані
 
Валідаційний набір: 5 знімків плоскої стіни, 40 опорних точок з відстанями, отриманими двома незалежними способами (геометрія маркерів і рулетка). Формат і походження описані в [`data/info.md`](data/info.md).
 
Дані зібрані командою самостійно, людей у кадрі немає, персональних даних набір не містить. Ліцензія: CC BY 4.0.
 
## План до фінального захисту
 
Критично необхідне:
 
- повторити вимірювання глибини на бортовій камері Tello;
- замкнути контур на передбаченій глибині, а не на ground truth, хоча б у replay-режимі;
- розширити валідаційний набір складними поверхнями: однотонні стіни, скло, дзеркала, тонкі об'єкти, контрове світло;
- отримати залежність частоти зіткнень від точності глибини.
Бажане, якщо дозволить час:
 
- реальні польоти Tello через смугу перешкод;
- абляція за частотою обробки кадрів і роздільною здатністю;
- постер.
